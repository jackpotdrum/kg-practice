## 問題文
あなたはEC企業の物流システム改善チームとして、タスク順序を変えずに1日の作業計画をK日以内へ分割する。
目的は、各日の合計負荷の最大値を最小化すること。

## 入出力仕様 / 制約
- 入力: N, K と長さNの配列 A
- 出力: K日以下に分割したときの「1日あたり合計負荷の最大値」の最小値
- 制約:
  - 1 <= N <= 2 * 10^5
  - 1 <= K <= N
  - 1 <= A_i <= 10^9
- 想定計算量: O(N log(sum(A)))

    low = max(dayly_tasks)

        else:

import argparse


def can_split_with_limit(tasks, k, limit):
    days = 1
    current = 0

    for x in tasks:
        if current + x <= limit:
            current += x
        else:
            days += 1
            current = x
            if days > k:
                return False
    return True


def minimize_max_daily_load(tasks, k):
    low = max(tasks)
    high = sum(tasks)

    while low < high:
        mid = low + (high - low) // 2
        if can_split_with_limit(tasks, k, mid):
            high = mid
        else:
            low = mid + 1

    return low

## 解説
- この問題は「答えの値」を二分探索する。
- 判定関数 can_split_with_limit(limit) は、limit 以下で1日を詰める貪欲法で必要日数を数える。
- 必要日数が K 以下なら成立、超えるなら不成立。
- 成立/不成立が単調に切り替わるため、最小の成立値を二分探索できる。

### 関数別の詳説

#### can_split_with_limit(dayly_tasks, k, limit)
- 目的: 「1日の上限を limit としたとき、K日以内に分割できるか」を True/False で判定する。
- 変数:
    - groups: 現時点で必要になった日数（区間数）
    - current_sum: いまの日に積んでいる合計負荷
- 流れ:
    - 配列を左から順に見る。
    - `current_sum + task <= limit` なら同じ日に task を積む。
    - 超えるなら日を切り替えて `groups += 1`、新しい日の先頭をその task にする。
    - 途中で `groups > k` になった時点で不可能確定なので False を返す。
    - 最後まで見て `groups <= k` なら True。
- なぜこの判定で正しいか:
    - 上限 limit が固定のとき、各日を可能な限り詰める貪欲法が必要日数を最小化する。
    - 早めに日を切っても必要日数は減らないため、この判定で「可能/不可能」を正しく判定できる。

#### minimize_max_daily_load(dayly_tasks, k)
- 目的: K日以下で分割できる「1日最大負荷」の最小値を求める。
- 探索範囲:
    - `low = max(dayly_tasks)`（これ未満は必ず不可能）
    - `high = sum(dayly_tasks)`（1日に全部積めば必ず可能）
- 流れ（最小の成立値を探す二分探索）:
    - `mid = (low + high) // 2` を仮の上限として判定。
    - 可能（True）なら、もっと小さい上限も試すため `high = mid`。
    - 不可能（False）なら、上限を上げるため `low = mid + 1`。
    - `low == high` になった値が最小の成立値。
- 重要ポイント:
    - ここでの二分探索は「配列要素探し」ではなく「答えの値域探索」。
    - 判定結果が `False -> ... -> False -> True -> ... -> True` と単調に切り替わるので二分探索できる。
    - `//` は整数の中点を取るために使う（本問の答えは整数）。

### 1回分のミニトレース（理解用）
- 例: `dayly_tasks = [8, 1, 7, 3, 9, 2, 6], k = 3`
- 初期: `low=9, high=36`
- `mid=22` -> 可能（例: [8,1,7,3], [9,2], [6]）なので `high=22`
- `mid=15` -> 不可能（[8,1], [7,3], [9,2], [6] で4日必要）なので `low=16`
- `mid` を更新しながら範囲を狭め、最終的に最小の成立値へ収束する。

## 計算量メモ
- 判定関数: O(N)
- 二分探索回数: O(log(sum(A)))
- 全体: O(N log(sum(A)))
- 追加メモリ: O(1)

## 学びの要点（再発防止チェックリスト）
- 二分探索は配列だけでなく「答えの値域」にも適用できる。
- 判定関数は単調性（False...False, True...True）を意識して設計する。
- 最小の成立値を探すテンプレート:
  - while low < high
  - true -> high = mid
  - false -> low = mid + 1

- mid の式や // と / の違いに不安があり、二分探索の更新式に自信が持てなかった。
