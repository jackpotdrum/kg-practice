# 二分探索（Binary Search）

## 概要

二分探索は「探索範囲を毎回半分に削る」手法。

- ソート済み配列から値を探す
- 条件を満たす最小値/最大値を探す（答え側探索）

の2種類が実戦で頻出。

計算量は探索回数が O(log N)（または O(log 範囲)）になるため、全探索より大幅に高速化できる。

## 1. どんな問題で使うか

次のキーワードが出たら候補にする。

- 「最小のX」「最大のX」
- 「Xなら可能か？」という判定関数が作れる
- 判定結果が単調に切り替わる
  - 例: False, False, False, True, True

典型例:

- ソート済み配列で target の位置を探す
- K日以内で処理できる最小容量
- 区間最大和を最小化する分割
- 制約を満たす最小コスト/最大しきい値

## 2. 二分探索の本質

二分探索の本質は次の2点。

1. 探索区間の定義（low, high）
2. 中央値 mid で「どちら側に答えがあるか」を決める判定

これが曖昧だと、無限ループやオフバイワンが起きる。

## 3. mid の式はどれが正しいか

どちらも正しい。

```python
mid = (low + high) // 2
mid = low + (high - low) // 2
```

- Pythonではどちらでも実質問題ない（整数が多倍長）
- 他言語（固定長整数）では後者がオーバーフロー安全

実戦では、言語をまたいで安全な次を習慣化すると迷いにくい。

```python
mid = low + (high - low) // 2
```

注意:

- `/` は浮動小数になるため、この種の整数二分探索では通常使わない
- `//` で整数の mid を作る

## 4. 配列探索版テンプレ

### 4-1. 1個見つける（存在判定）

```python
def binary_search_exists(arr, target):
    low, high = 0, len(arr) - 1

    while low <= high:
        mid = low + (high - low) // 2
        if arr[mid] == target:
            return True
        if arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1

    return False
```

### 4-2. lower_bound（target以上の最初の位置）

```python
def lower_bound(arr, target):
    low, high = 0, len(arr)  # [low, high)
    while low < high:
        mid = low + (high - low) // 2
        if arr[mid] >= target:
            high = mid
        else:
            low = mid + 1
    return low
```

## 5. 答え側探索テンプレ

「最小の成立値」を探す型。

- 判定関数 `is_ok(x)` を用意
- `x` が大きいほど成立しやすい（単調）

```python
def find_min_ok(low, high, is_ok):
    # 前提: 答えは [low, high] に存在し、high は成立する
    while low < high:
        mid = low + (high - low) // 2
        if is_ok(mid):
            high = mid
        else:
            low = mid + 1
    return low
```

今回の `minimize_max_daily_load` はこの型そのもの。

## 6. 正しさチェック（毎回確認）

実装前に次を1行で言えるか確認する。

1. low は何を表すか
2. high は何を表すか
3. is_ok(mid) が True のとき、どちらへ寄せるか
4. ループ停止後の low/high が何を意味するか

これを言語化できると、更新式を間違えにくい。

## 7. よくあるミス

- `/` を使って mid が float になる
- `while low <= high` と更新式の組み合わせを混同する
- True 側/False 側の寄せ方が逆
- 探索区間の端（閉区間/半開区間）を混ぜる
- 判定関数に単調性がないのに二分探索してしまう

## 8. 計算量

- 1回の判定が O(T)
- 二分探索回数が O(log R)（R は探索範囲の大きさ）
- 全体 O(T log R)

例:

- `can_split_with_limit` が O(N)
- 探索範囲が `max(A) ... sum(A)`
- 合計 O(N log(sum(A)))

## 9. 30分試験での実戦手順

1. 単調性のある判定関数を先に作る
2. low/high の意味をコメントで固定する
3. テンプレ通りにループを書く
4. 境界ケースで確認する
   - 最小入力
   - 全部同じ値
   - K=1
   - K=N

## 10. デバッグ観点（詰まったとき）

次を1行ログで出すと原因が見えやすい。

- `low`, `high`, `mid`
- `is_ok(mid)` の結果
- 更新後の `low`, `high`

ログ例:

```text
low=9 high=36 mid=22 ok=True -> high=22
low=9 high=22 mid=15 ok=False -> low=16
...
```
