# スライディングウィンドウ（Two Pointers）

## 概要

連続区間を対象に、左右ポインタ（`left`, `right`）で区間を動かして解く手法。

- `right` を進めて区間を広げる
- 条件を満たしたら `left` を進めて区間を縮める

各要素を「入れる」「出す」を高々1回ずつ行うため、O(N) で解けるケースが多い。

## 1. どんな問題で使うか

次のようなキーワードが問題文に出たら、まず候補にします。

- 連続区間（部分列ではなく連続）
- 最短/最長の区間
- 条件を満たす区間数、または条件を満たす区間そのもの
- 「少なくとも K 個」「重複を含めて」「種類数」など、区間内の状態で判定できる

典型例:

- 文字列で重複なしの最長部分文字列
- 和が S 以上になる最短部分配列
- 条件を満たす最短/最長の連続区間
- 区間内の種類数が K 以下の最長区間

## 2. 使わない方がよいケース

- 判定が区間内だけで完結しない（全体依存が強い）
- 並び替えが必要な問題（順序を壊すと成立しない）
- 区間ではなく任意部分集合を選ぶ問題

## 3. 実装前に決めること

実装に入る前に、次の3点を日本語で1行ずつ決める。

1. 区間に要素を入れるときの更新ルール（`add`）
2. 区間から要素を外すときの更新ルール（`remove`）
3. いつ `left` を動かすか（縮小条件）

この3点が曖昧だと、実装の while 条件で迷って崩れる。

## 4. 基本テンプレ（最短区間）

```python
from collections import defaultdict


def solve_shortest_window(events, required_counts):
    # 任意: 達成不能ケースの早期終了
    total_counts = defaultdict(int)
    for event in events:
        if event in required_counts:
            total_counts[event] += 1

    for event_type, need in required_counts.items():
        if total_counts[event_type] < need:
            return -1

    target_type_count = len(required_counts)
    satisfied_type_count = 0
    window_counts = defaultdict(int)

    best_window = None  # (length, left, right)
    left = 0

    for right, event in enumerate(events):
        if event in required_counts:
            window_counts[event] += 1
            if window_counts[event] == required_counts[event]:
                satisfied_type_count += 1

        # 条件を満たしている間は縮め続ける
        while satisfied_type_count == target_type_count and left <= right:
            candidate = (right - left + 1, left, right)
            if best_window is None or candidate < best_window:
                best_window = candidate

            left_event = events[left]
            if left_event in required_counts:
                if window_counts[left_event] == required_counts[left_event]:
                    satisfied_type_count -= 1
                window_counts[left_event] -= 1
            left += 1

    if best_window is None:
        return -1

    length, left_idx, right_idx = best_window
    return left_idx + 1, right_idx + 1, length  # 1-indexed
```

## 5. バリエーション

### 5-1. 最長区間を求める

- 条件を破ったときだけ `left` を動かす
- 条件を満たしている間に `max_len` を更新

```python
left = 0
best_len = 0
for right, x in enumerate(arr):
    add(x)
    while is_invalid():
        remove(arr[left])
        left += 1
    best_len = max(best_len, right - left + 1)
```

### 5-2. 条件を満たす区間数を数える

- 各 `right` で有効な `left` の範囲を数え上げる
- 問題ごとに加算式が変わる（`right-left+1` など）

## 6. 書くときのチェックポイント

- `while` を回す条件は「条件を満たしている間」になっているか
- 左を1つ外すとき、達成状態のカウンタを先に落とす必要があるか
- タイブレークをタプル比較で表現できているか
  - 例: `(区間長, l, r)`
- 0-index/1-index 変換を最後にまとめているか
- サンプルに対して出力形式まで一致しているか

## 7. 計算量の考え方

- 右端 `right` は 0 から N-1 まで1回ずつ進む
- 左端 `left` も後ろにしか進まないので全体で高々 N 回
- よって時間計算量は O(N)
- 追加メモリは状態管理に使う辞書や配列分で O(K)
    - K は保持するキー種類数

## 8. 30分試験での実戦手順

1. 問題文を読んで「連続区間」「最短/最長」「区間内条件」を確認
2. `add/remove/縮小条件` を1行ずつメモする
3. 先に O(N) の骨組みを書く（for right / while 条件）
4. 最後にタイブレークと出力形式を整える
5. サンプルと反例1つ（不成立ケース）で確認

## 9. よくあるミス

- `len(section)` を区間長の代わりに使ってしまう
- 最短候補の更新より先に左を動かしてしまう
- 満たした種類数（`met`）の増減条件を間違える
- 1-indexed 出力を忘れる

## 10. デバッグ観点（詰まったとき）

次を1行ログで出すと、ほぼ原因が見える。

- `right`, 入れた値, `left`, `window_counts`, 条件達成フラグ
- while 内で更新した候補と、left を進めた後の状態

ログ例:

```text
r=7 add=4 left=1 met=3 counts={2:3,4:1,5:1}
update best=(7,1,7)
shrink left=2 met=3 counts={2:2,4:1,5:1}
...
```
