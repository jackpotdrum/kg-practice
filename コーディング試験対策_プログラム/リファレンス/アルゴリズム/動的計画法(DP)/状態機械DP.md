# 状態機械DP

## 概要

状態機械DPは、

- 時系列に沿って意思決定する
- 現在の「モード（状態）」に応じて次の遷移先が決まる
- モード変更にコストや回数制約がある

という問題を解くためのDP。

「何を選ぶか」だけでなく「今どの状態にいるか」を明示的に持つのが特徴。

## 1. どんな問題で使うか

次のキーワードがあると有力。

- ON/OFF、A/B/C など離散的な状態がある
- 連続維持ボーナス、切り替えペナルティがある
- 切り替え回数、使用回数、在庫などの資源制約がある
- その場の最善（貪欲）だと全体最適にならない

典型例:

- 売買DP（未保有/保有、取引回数制限）
- 休みあり活動計画（活動状態と休憩状態）
- モード切替つき最小コスト運用
- 戦略切替回数制限つき最大利益

## 2. 形式化（汎用形）

時点 `t`（0..N-1）ごとに、状態 `s`（0..S-1）を取る。

- `dp[t][s][r]`
  - 時点 `t` まで見た
  - 最後の状態が `s`
  - 資源消費量が `r`
  - の最適値（最大 or 最小）

メモリ削減版では `prev[s][r]`, `cur[s][r]` の2層で十分。

## 3. 設計手順

実装前に次を先に決める。

1. 状態集合 `S`
- 問題文の「モード」「保有/非保有」「連続中/非連続中」を洗い出す

2. 資源軸 `R`
- 回数制約、コスト上限、在庫など必要なら追加する

3. 遷移規則
- `from_state -> to_state` の可否
- 資源消費量の増減
- 価値への加算/減算

4. 初期状態
- `t=0` で到達可能な状態のみ値を入れる
- 未到達は十分悪い値（`-INF` または `INF`）

5. 答えの取り方
- `t=N-1` の全状態から最適値を取る

## 4. 汎用テンプレ（最大化）

```python
def state_machine_dp(N, S, R, gain, transitions, init_states):
    # gain(t, to_state): 時点tで to_state を選んだときの増分
    # transitions: (from_state, to_state, resource_cost)
    NEG_INF = -10**30
    prev = [[NEG_INF] * (R + 1) for _ in range(S)]

    # 初期化
    for s, r0, base in init_states:
        prev[s][r0] = base + gain(0, s)

    for t in range(1, N):
        cur = [[NEG_INF] * (R + 1) for _ in range(S)]

        for fs in range(S):
            for r in range(R + 1):
                if prev[fs][r] == NEG_INF:
                    continue

                for (from_s, to_s, rcost) in transitions:
                    if from_s != fs:
                        continue
                    nr = r + rcost
                    if nr > R:
                        continue
                    cand = prev[fs][r] + gain(t, to_s)
                    if cand > cur[to_s][nr]:
                        cur[to_s][nr] = cand

        prev = cur

    ans = max(max(row) for row in prev)
    return ans
```

ポイント:

- 遷移規則をデータ化すると拡張しやすい
- 最大化なら未到達は `NEG_INF`、最小化なら `INF`

## 5. A/B切り替え問題との関係

今回の問題は、上の汎用形で次の特別ケース。

- 状態数 `S=2`（A, B）
- 資源 `R=K`（切り替え回数）
- 同一状態遷移の `rcost=0`、切替遷移の `rcost=1`

つまり「状態機械DPの基本形そのもの」であり、特殊問題ではない。

## 6. なぜ最適解が得られるか

1. 状態が十分
- 未来の意思決定に必要な情報だけを状態に保持している

2. 遷移が完全
- 許される全遷移を毎時点で列挙している

3. 同一状態では最良値のみ保持でよい
- 同じ状態に到達した2経路では、値が良い方だけ残せば将来も不利にならない

以上より、最終時点の最大値が全体最適と一致する。

## 7. 計算量

一般形:

- 時間: O(N * R * E)
  - `E` は状態遷移数
- 空間: O(R * S)

A/B切替型（状態2つ、遷移定数個）:

- 時間: O(NK)
- 空間: O(K)

## 8. よくあるミス

- 状態に必要な情報を落としてしまう
- 遷移の資源増減（+1 など）を逆に書く
- 初期化で到達不能状態に値を入れてしまう
- `prev` を上書きして同時刻遷移を混ぜる
- 最大化/最小化の未到達番兵値を逆にする

## 9. デバッグ観点

詰まったら次を1時点だけ出力する。

- `prev` の有効状態一覧
- 各遷移で作った候補値 `cand`
- `cur` の更新結果

最小ケース（N=2,3）で手計算と一致すれば、遷移定義はほぼ正しい。
